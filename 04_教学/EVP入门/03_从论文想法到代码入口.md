## 任务一：找到程序从哪里开始

**问题：只打开模型文件，能知道训练哪个任务吗？**

不能。先看 `train.py` 的主入口：读取 `--config`，再调用 `main`；`main` 创建数据加载器、模型与优化器，按轮次调用 `train`。一次训练批次的路线是：

`配置 → 图片与掩码 → set_input → optimize_parameters → 前向计算 → 损失 → 反向传播 → 更新参数`。

以失焦示例配置为条件，可以读出输入为 320×320、批量为 4、50 轮、AdamW 学习率为 0.0002。它们是作者提供的配置值，并非已经在本机成功运行的记录。[train.py：main、train][train] · [失焦配置][config]

**自测答案：**换任务至少检查数据路径、模型分支、损失和 `eval_type`；只改图片目录不够。先在纸上画出上述箭头，无须运行命令。

## 任务二：一张图片如何配上标准答案

**问题：为什么还要有第二个文件夹？**

`PairedImageFolders` 从两个目录取相同索引的文件：第一个是 RGB 图片，第二个是灰度掩码。掩码相当于逐像素答案。`ImageFolder` 默认分别排序文件名，因此“目录中文件数相同”不能证明正确配对；真正复现前应核对名称对应和训练、验证样本是否重叠。[image_folder.py：ImageFolder、PairedImageFolders][data]

`TrainDataset.__getitem__` 对图与掩码同步左右翻转、缩放，再把图像转成张量并按通道归一化。值得练习的是：配置写 `augment: false`，但这段翻转判断没有读取 `self.augment`，仍按随机概率执行。**答案：配置表达意图，执行分支决定行为。**这里没有实际抽样检查增强结果。[wrappers.py：TrainDataset][wrapper]

## 任务三：“冻结”究竟冻结什么

**问题：冻结主干后，所有参数都不能学习了吗？**

在 `SegFormer.__init__` 的 `evp` 分支，参数名不包含 `prompt`、也不包含 `decode_head` 时，设置 `requires_grad = False`。因此保留学习的包括提示生成器和解码头；不能理解为“只训练几个提示数字”。冻结表示不更新相应参数，主干仍参与前向计算，并可把梯度传回前面的可训练模块。[segformer.py：参数冻结][freeze]

解码头把四级特征投影、调整到共同空间尺寸、拼接融合，最后生成单通道分割分数。[SegFormerHead.forward][head]

**自测答案：**不能从 README 的参数比例直接推出当前配置的可训练数量。以后运行时应分别统计总参数和 `requires_grad=True` 参数，再确认实际更新情况；本次没有做这项运行验证。

## 任务四：高频与提示怎样进入主干

**问题：这里的 prompt 是人输入的一句中文吗？**

不是。失焦配置选择 `name: evp`、`input_type: fft`、`prompt_type: highpass`。`PromptGenerator.fft` 对输入做傅里叶变换，用尺寸由 `freq_nums` 决定的中央方形掩码去掉一部分低频，再逆变换并取绝对值。可以先把低频理解为缓慢变化的区域，高频理解为快速变化的细节；高频也可能含噪声，不能直接等同于“目标边界”。[PromptGenerator.fft][fft]

`init_handcrafted` 将这一路信号变成多级特征；`init_prompt` 对原有嵌入做线性映射。`get_prompt` 合并两路，经当前层的小 MLP 和同阶段共享映射，得到可相加的特征。关键一行是 `x = x + feat`。`forward_features` 在 Transformer 块之前调用它，提示因此随当前图像变化。[提示生成与注入][prompt]

**自测答案：**原始图片、频率信号、嵌入特征和最终分割图是不同对象；请画四个框，标出提示添加在中间特征处。

## 任务五：怎样阅读扩展版的频率适配器

**问题：仓库里所有带 Fourier 的代码都和上一节相同吗？**

不相同。另一个配置选择 `name: fp`，进入 `mix_transformer_fourierprompt.py`。`FrequencyAdaptor.get_frequency` 沿特征张量的倒数第二维做实数傅里叶变换，用两个线性层加 Sigmoid 分别产生实部、虚部掩码，然后逆变换。其 `forward` 将频率与嵌入两路降维、分别处理、合并升维；这与上一节输入端固定高通掩码有明确差别。[fp 配置][fpconfig] · [FrequencyAdaptor][frequency]

**自测答案：**看到可学习频率掩码和适配器，是具体模块的静态证据，尚不等于期刊版所有实验都可复现。尤其 `SegFormer.__init__` 的冻结条件显式列出 `evp` 等分支，却没有对应的 `fp` 条件；不能直接把上一节“冻结主干”的结论套到 `fp`。应先核查参数状态，再谈参数效率。

## 任务六：模型靠什么知道自己错了

**问题：文件里出现多种损失，训练时会全部使用吗？**

不会。失焦配置选择 `loss: bce`，实际 `backward_G` 使用二元交叉熵，让像素预测接近掩码；选择 `iou` 时才额外加重叠损失。`optimize_parameters` 依次前向、清空旧梯度、反向、更新。不要因为注释写了 “GAN and L1”，就断定这条训练链使用生成对抗训练；应看执行表达式。[segformer.py：损失与参数更新][loss]

**自测答案：**损失是训练时的优化目标，评价指标是检查结果的尺度。它们可以相关，但名称、计算方式和用途不必相同。

## 任务七：怎样避免读错实验结果

**问题：函数名叫 `eval_psnr`，它一定计算 PSNR 吗？**

不是。它按 `eval_type` 选函数：失焦示例的 `fmeasure` 调用 `calc_fmeasure`，返回 F-measure 与 MAE；其他分支包含 F1/AUC、BER、COD 和 SOD 指标。F-measure 综合查准率与查全率，MAE 是平均绝对误差。还要读阈值与汇总方式：此实现先处理各图，再在一个批次内合并像素计算 F-measure，外层再汇总批次。不同实现可能得出不同数字。[test.py：eval_psnr][eval] · [utils.py：calc_fmeasure][metric]

**自测答案：**读表前记录数据划分、图像尺寸、阈值、指标方向、汇总粒度及权重来源。`train.py.save` 对 `evp` 保存提示生成器和解码头，测试还需配套主干权重；只有一个提示文件不能视为完整模型。[train.py：save][save]
